# PicBerth v0.0.2

## 中文

本版本改进后台任务、数据维护、构建验证和部署文档。

### 改进与修复

- 修复缩略图回填被缺失或损坏记录阻塞的问题；新增与分页查询匹配的索引，减少大型图片库中的队列查询开销。
- 快速检查会重试清除已永久删除图片的原图与缩略图残留；文件遍历分批读取，避免一次积累全部文件列表。
- 审计写入独立于客户端断开；错误初始化请求不再耗尽正确初始化代码所需的全局额度。
- 显式空环境变量和命令行参数正确覆盖配置文件中的值；开发 Web 目录使用根目录约束。
- Docker 运行时升级至 distroless Debian 13 nonroot；部署示例固定 Caddy 镜像摘要并设置日志轮转。
- pnpm 升级至 12.18.0，Vite 升级至 8.3.7；保留锁文件、依赖发布观察期和构建脚本限制。
- CI 的测试、交叉编译、E2E 与双架构 Docker 构建并行运行，仍由完整门禁约束；发布演练保留可下载核验的 OCI 归档。
- 新增英文 README，并校正两种语言的初始化、反向代理、快照恢复和产物校验说明。

### 下载与升级

- 原生程序：Linux AMD64 / ARM64、Windows AMD64、macOS ARM64。
- Docker 标签：`ghcr.io/dejavumoe/picberth:v0.0.2`，支持 Linux AMD64 / ARM64。
- 压缩包包含程序和 MIT 许可证；`SHA256SUMS` 为独立附件。正式发布的压缩包有 GitHub 构建证明，镜像包含 SBOM 和 provenance。

升级前停止服务并创建可信快照。首次启动会将元数据库升级到 schema 4，并在 `<数据目录>/backups/` 保存迁移前副本；图片文件不会被迁移。旧程序不能直接打开 schema 4 数据库，回退时应停止服务并恢复对应旧版本的备份。

本版本准备与正式发布状态以 GitHub Release 为准；演练 artifact 不代表已经发布。数据仍需存于本地磁盘，重要图片应保留独立备份。

## English

This version improves background work, data maintenance, build verification, and deployment documentation.

### Improvements and fixes

- Thumbnail backfill continues past missing or broken records. A matching pagination index reduces queue lookup work in large libraries.
- Quick checks retry removal of original images and thumbnails left behind after permanent deletion. File walks read directory entries in batches instead of accumulating the whole file list.
- Audit writes survive client disconnects. Invalid setup requests no longer consume the global allowance needed by a valid setup code.
- Explicitly empty environment variables and CLI flags override configuration-file values. Development web directories use root confinement.
- Docker runtime moves to distroless Debian 13 nonroot. Deployment examples pin the Caddy image digest and rotate container logs.
- pnpm moves to 12.18.0 and Vite to 8.3.7, retaining lockfiles, the dependency release-age policy, and build-script restrictions.
- CI tests, cross-compilation, E2E, and both Docker architectures run in parallel under the full required gate. Release rehearsals retain downloadable OCI archives for verification.
- An English README accompanies the Chinese README, with corrected setup, reverse-proxy, snapshot-restoration, and artifact-verification instructions.

### Downloads and upgrading

- Binaries: Linux AMD64 / ARM64, Windows AMD64, and macOS ARM64.
- Docker tag: `ghcr.io/dejavumoe/picberth:v0.0.2`, for Linux AMD64 / ARM64.
- Archives contain the binary and MIT license; `SHA256SUMS` is a separate asset. Published archives have GitHub build attestations, and images include an SBOM and provenance.

Stop the service and create a trusted snapshot before upgrading. The first startup migrates metadata to schema 4 and saves a pre-migration copy under `<data-dir>/backups/`; image files are unchanged. Older binaries cannot open schema 4 directly. Stop the service and restore the matching older backup before rolling back.

Use the GitHub Release to determine publication status; rehearsal artifacts are not a published release. Store data on local disk and retain independent backups of important images.
